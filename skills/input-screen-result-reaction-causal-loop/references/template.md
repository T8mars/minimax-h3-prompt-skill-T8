# 输入—屏幕—结果—反应｜实体操作与虚拟反馈逐拍闭环 Template

## Mechanism

Establish one original clearly adult operator, a physical input device and a visible response display in the same geography. For every important virtual event, show one specific physical input first, then the corresponding screen or machine response, then a readable operator reaction when appropriate. Escalate from selection through locomotion and defense to one decisive result. Reconnect the result to the same adult rather than ending on the interface alone. The reusable mechanism is input-before-output evidence, device-screen correspondence, escalating task states and human-result closure—not the source woman, arcade, game, characters, cabinet, controls, moves, venue, creator identity or timing.

## Invariants

### inv-01

- Rule: Establish one clearly adult operator, physical controls and response display together.
- Purpose: Creates a verifiable causal system.
- Failure if removed: Screen-only footage cannot prove who caused the action.

### inv-02

- Rule: Show each important physical input before its matching virtual response.
- Purpose: Preserves temporal causality.
- Failure if removed: Output-first editing makes control correspondence ambiguous.

### inv-03

- Rule: Use at least three different input-response pairs rather than repeating one button.
- Purpose: Demonstrates a reusable control grammar.
- Failure if removed: A single repeated action provides little mechanism breadth.

### inv-04

- Rule: Escalate from setup and navigation to one decisive result state.
- Purpose: Builds a complete task arc.
- Failure if removed: Disconnected interactions feel like a demo reel.

### inv-05

- Rule: End by reconnecting the result to the same adult's readable reaction.
- Purpose: Closes machine evidence with human meaning.
- Failure if removed: An interface-only ending loses the operator.


## Variable Slots

| Slot | Constraint |
|---|---|
| lead_subject | An original stable subject or pair with a readable role. |
| setting | A new setting with fixed spatial anchors and no source-specific surface. |
| escalation_variable | One causal variable that changes through visible stages. |
| performance_rule | A restrained acting or motion rule that keeps the mechanism legible. |
| camera_grammar | An information order that proves each state without copying source shot boundaries. |
| payoff | A clean final physical, informational or social consequence. |
| sound_family | An original hierarchy of diegetic cues; no unsupported source-audio claim. |

## Anti-Copy Boundary

- source adult woman, face, clothes and reactions
- source Japanese arcade venue, cabinet and game screen
- source game characters, moves, selection and knockout interface
- source token, joystick, buttons and exact hand actions
- source camera route, Seedance 2.5 wording, creator identity and timing
