# 多功能救援线｜跨裂隙送补给再撤离 Template

## Mechanism

Introduce one compact traversal tool before the destination is reachable, then reuse the same line or tether through launch, climb, pendulum redirect and entry. Every phase must preserve the attachment point and route geometry; after one brief contact establishes the rescue choice, one subject visibly leads and both leave together without claiming the source tether carries them during departure.

## Invariants

### inv-01

- Rule: Introduce one unreachable destination and one compact traversal tool together.
- Purpose: Defines the problem and available solution.
- Failure if removed: A tool without a visible destination has no narrative role.

### inv-02

- Rule: Keep one tether and one stable attachment through launch and its first visible route role.
- Purpose: Makes the tool progression physically inspectable.
- Failure if removed: Changing lines or hidden anchors breaks continuity.

### inv-03

- Rule: Reuse the tether for at least three distinct route roles.
- Purpose: Creates the mechanism's progression.
- Failure if removed: A single swing is only an action beat.

### inv-04

- Rule: Make one brief contact inside the destination establish the rescue choice.
- Purpose: Turns traversal into a social objective.
- Failure if removed: A decorative arrival has no payoff.

### inv-05

- Rule: After contact, keep both subjects visibly leaving together with one subject leading.
- Purpose: Closes the access-to-rescue chain without overclaiming tether use.
- Failure if removed: Cutting away after contact leaves the rescue choice unproven.


## Variable Slots

| Slot | Constraint |
|---|---|
| lead_subject | An original stable subject or pair with a readable role. |
| setting | A new setting with fixed spatial anchors and no source-specific surface. |
| escalation_variable | One causal variable that changes through visible stages. |
| performance_rule | A restrained acting or motion rule that keeps the mechanism legible. |
| camera_grammar | An information order that proves each state without copying source shot boundaries. |
| payoff | A clean final physical, informational or social consequence. |
| sound_family | An original hierarchy of diegetic cues; no unsupported source-audio claim. |
