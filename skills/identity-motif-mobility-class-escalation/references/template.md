# 身份机体跃迁｜同一特征跨陆空载具升级 Template

## Mechanism

Establish one unmistakable identity motif before any transformation, then migrate that motif through a sequence of complete mobility bodies whose functional class visibly escalates. Each stage must preserve at least two identity anchors while adding one readable new mobility affordance; do not replace one object with an unrelated one. Reserve the largest category change for the final stage and hold the completed identity-machine hybrid long enough to verify both continuity and new function.

## Invariants

### inv-01

- Rule: Establish one identity motif with at least two stable visual anchors before machine integration begins.
- Purpose: Creates an auditable identity baseline.
- Failure if removed: Starting on a hybrid gives no proof that identity survived the transition.

### inv-02

- Rule: Show the motif physically merging with the first mobility body rather than cutting to a finished replacement.
- Purpose: Binds carrier change to the original identity.
- Failure if removed: A hard swap reads as unrelated object replacement.

### inv-03

- Rule: Complete one functional mobility class while keeping the identity anchors visibly active.
- Purpose: Proves that the hybrid is more than decorative texture.
- Failure if removed: A static themed shell does not demonstrate a carrier role.

### inv-04

- Rule: Escalate through another mobility realization with a visibly different affordance.
- Purpose: Builds a capability ladder instead of repeated reskins.
- Failure if removed: Changing only color or bodywork leaves the mechanism flat.

### inv-05

- Rule: Finish with one larger mobility-class change and hold identity plus function together.
- Purpose: Delivers a terminal category payoff.
- Failure if removed: Ending mid-morph prevents verification of the new class.
