# 功能问答闭环｜人物疑问由设备状态完成证明 Template

## Mechanism

Place one original questioner and one visibly operating device in the same opening frame so the functional uncertainty has a physical anchor. Cut once to a second adult who checks a separate status carrier and gives a visible response; do not rely on unreadable UI or prescribed dialogue. Return to the opening device space and change one machine state plus the questioner's posture or expression, so device evidence and human interpretation close the loop together. The reusable mechanism is question, remote status check, machine-state proof and return—not the source people, faces, clothes, home, computer hardware, phone, product, logo, dialogue, exact gestures, composition, creator identity or timing.

## Invariants

### inv-01

- Rule: Open with the questioner and the relevant operating device visible in one spatial relationship.
- Purpose: Gives the abstract function a concrete proof anchor before any answer.
- Failure if removed: A face-only question leaves later device evidence unbound.

### inv-02

- Rule: Use a second adult and one separate status carrier as an independent response channel.
- Purpose: Turns the answer into an observable relay rather than a title card.
- Failure if removed: Keeping every claim with the first person collapses question and proof into assertion.

### inv-03

- Rule: Avoid depending on small interface text or exact spoken words.
- Purpose: Keeps the mechanism supported by visible state and performance evidence.
- Failure if removed: Unreadable UI or untranscribed dialogue cannot carry the causal claim.

### inv-04

- Rule: Return to the opening device space after the response.
- Purpose: Reconnects the remote interpretation to the original physical system.
- Failure if removed: Ending on the phone makes the machine's result ambiguous.

### inv-05

- Rule: Change one device state and one human response before the final hold.
- Purpose: Provides both functional and social confirmation.
- Failure if removed: A static machine or unchanged questioner does not resolve the setup.

## Anti-Copy Boundary

- the source adults, faces, bodies, clothing, expressions and exact gestures
- the source domestic rooms, balcony door, desktop computer, monitor, phone, couch and furniture
- the source product, deAPI and Earn Module concepts, logos, interface state and copy
- the source dialogue implication, camera positions, edit timing, color grade and performance rhythm
- the source creator identity, MiniMax H3 claim, platform overlay, watermark and branding
