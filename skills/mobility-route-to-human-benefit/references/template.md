# 移动兑现｜载具跃迁到生活结果 Template

## Mechanism

A mobility proof becomes meaningful when an identified carrier departs, demonstrates one unmistakable capability upgrade, crosses a legible route, arrives at a specific destination, and hands the sequence to a human-scale benefit. The beneficiary action must visibly consume or use the delivered result rather than merely posing beside it.

## Invariants

### inv-01

- Rule: Establish the carrier and departure point before accelerating the route.
- Purpose: Gives the journey a concrete origin.
- Failure if removed: Opening mid-flight removes the state change and route promise.

### inv-02

- Rule: Use one visible capability upgrade that changes how the carrier traverses space.
- Purpose: Creates a technical proof rather than ordinary travel.
- Failure if removed: Decorative light with no route effect is not an upgrade.

### inv-03

- Rule: Preserve a readable destination transition instead of random travel montage.
- Purpose: Connects performance to arrival.
- Failure if removed: Unrelated locations make the journey untraceable.

### inv-04

- Rule: Present the delivered object or service in tactile close detail at arrival.
- Purpose: Turns distance into a concrete result.
- Failure if removed: Skipping arrival detail leaves the benefit abstract.

### inv-05

- Rule: End with a beneficiary visibly using the result.
- Purpose: Completes the technology-to-life causal chain.
- Failure if removed: A product beauty shot does not prove human benefit.

| Slot | Constraint |
